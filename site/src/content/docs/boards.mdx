The boards [Start a project](../start/) and `cargo generate` offer. This

[`template/boards.toml`](https://github.com/joeferner/rpi-hal/blob/main/template/boards.toml).

**The kernel filename isn't a convention.** The firmware picks the one it
looks for from the CPU it finds (and, on a Pi 3 or 4, from `arm_64bit` in
`config.txt`). Finding none, it stops without printing anything, which
looks exactly like a dead board.

**ARMv6 needs nightly Rust.** `armv6-none-eabi` is a tier-3 target with
no precompiled `core`, so the project builds one with `-Z build-std`. The
generated project's `rust-toolchain.toml` takes care of it.

**The Pi 4 and Pi 5 have no interrupt controller in rpi-hal yet**, so
Embassy's time driver can't run there. The template's starter project
doesn't use interrupts, so it runs on every board above.

**The Pi 5 is preliminary, and its card is different.** Its boot
firmware lives in the board's EEPROM, so the card holds no firmware
files: just `config.txt` and the loader as `kernel8.img`. The
`config.txt` the project generates is what makes it boot: `os_check=0`
(the firmware otherwise refuses a kernel with no matching device tree),
`kernel_address=0x80000`, and `pciex4_reset=0`, which keeps the PCIe
link to the RP1 chip up, since the console's GPIO14/15 are on RP1. Only
the drivers listed under [Supported devices](../supported-devices/)
exist for it so far.

The Raspberry Pi Zero 2 W isn't supported yet. See
[Supported devices](../supported-devices/).
